03 / TECHNICAL COMPARISON与参考项目 qualcomm-volte-enabler 的逐层实测对比。

和参考项目的区别：
从单字节脚本到完整 32 位通话栈。

ikimi615/qualcomm-volte-enabler 为黑莓 KEY2（骁龙 660 原厂安卓 8.1）提供了宝贵的 /dev/diag 启发，但在高通 32 位平台 + Android 11 上存在五个维度的代际断层。

技术维度 qualcomm-volte-enabler（黑莓 KEY2 参考项目） 本项目 qcom32-volte（高通 32 位 Android 11 通用栈）
目标平台与架构边界 骁龙 660（SDM660，64 位 arm64-v8a），原厂 Android 8.1 已内置高通闭源 ims.apk 框架。 高通 32 位平台（MSM8974，armeabi-v7a），补齐 LineageOS 18.1（Android 11）完全缺失的现代 ImsService 框架层。
/dev/diag 内核协议 打包 64 位预编译 efs_Write，在 32 位系统无法运行；其指针式 ioctl 在 MSM8974 内核返回 EINVAL (-22)，且 MEMORY_DEVICE_MODE 会拦截 EFS 读写。 源码可见 32 位 C pp_regconfig_provision_v6 (PolyForm Noncommercial 1.0.0; commercial license available).
基带 EFS 写入深度 仅将 /nv/item_files/ims/IMS_enable 单字节改为 01。在 Passport 真机实测（1.61/1.62/1.81）中，单改此项仍报 CAUSE_CODE 54、完全无法注册。 解压 11.7MB Q6ZIP 基带固件逆向定位根因：协同配置 54 项 EFS/DS（405B 动态 PCO qp_ims_reg_config + 789B IPV4V6 profile4 + 独立 DCM 模式）。
Android 通话与来电显示 无任何 Android 端代码（文档提及的 qcril.db 与开机脚本在仓库 4 个脚本中均未实现）。 从零实现通用 Qcom32VolteIms.apk v2.8（rild_ims0 Protobuf 引擎、持久化 CarrierConfig、修正 3GPP CLIP→OIR 极性反转与 TOA=145 国际前缀，彻底解决“未知来电”）。
Root 前提与备份回滚 依赖刷入 Magisk；auto_enable_volte.sh 无修改前备份、读失败仍强写、无回滚程序。 检查日志仅含状态和哈希；固定回滚不保证还原原值。
完整代码级审计证据与里程碑对照已公开归档。 阅读完整技术对比报告

Magisk?

实测 ROM 的桌面方式可使用 ADB Root；不同 ROM 的权限支持需自行确认。

SELinux / EFS

实测设备保持 Enforcing；写入前应独立备份本机 EFS。

银色版和其他版本是否验证？

一台 oslo 在指定 ROM 上完成实验通话。oslo、wichita、keian、wseries 和 windermere 默认只读，保留回滚。

早期已安装旧包名 org.passport.volteims 的设备如何升级？

完全自动！运行 v1.2.8-r1 的桌面一键版或 CLI 时，工具会自动清理旧包残留、平滑迁移至新通用包名 org.octolab.qcom32ims（v2.8）并重新绑定持久化 CarrierConfig。

来电显示正常吗？为什么早期方案会显示“未知号码”？

通话栈处理 3GPP CLIP 与 Android ImsCallProfile.OIR 的极性差异及国际号码格式；来显仅在此前一台联通 46001 wolverine 上实测，v2.8 本轮仅经离线/模拟验证。

重启后无信号或提示基带不兼容怎么办？

v1.2.8-r1 修正了运行时基带省略 MPSS 前缀（如 .DI.4.0.1-00158-M8974AAAAANAZM-1）及免 Root 只读体检的误判，保留旧 IMS 守护进程（例如 imsqmidaemon）与基带预检，并在回滚无法打开 /dev/diag 时提示先恢复机外备份或刷回原版 AAB982 NON-HLOS.bin；这些保护仅经离线/模拟验证，不保证恢复信号或原值。源码中的实验机型授权同样不能跳过预检。

回滚能还原原值吗？

不能保证。检查日志并非完整备份；固定清理会写入 00 并删除条目。请提前独立备份。

支持紧急呼叫（110/119/120/911）吗？

本项目属于实验性经典硬件救援方案，未经过运营商或紧急呼叫中心（E911/IMS Emergency PDN）认证。请勿将修改后的老手机作为唯一的紧急求救联络工具。
