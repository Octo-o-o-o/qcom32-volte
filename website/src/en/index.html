03 / TECHNICAL COMPARISONCode-level & live-hardware audit vs ikimi615/qualcomm-volte-enabler.

How this differs from
qualcomm-volte-enabler.

ikimi615/qualcomm-volte-enabler inspired initial /dev/diag exploration on BlackBerry KEY2 (SDM660 Android 8.1), whereas 32-bit MSM8974 on Android 11 required solving five structural gaps.

Dimension qualcomm-volte-enabler (KEY2 Reference) qcom32-volte (32-Bit Qualcomm Android 11 Stack)
SoC, ABI & OS Snapdragon 660 (arm64-v8a), stock Android 8.1 already ships Qualcomm’s proprietary ims.apk stack. 32-bit Qualcomm (MSM8974, armeabi-v7a), bridging LineageOS 18.1 (Android 11) where ImsService is completely absent.
/dev/diag Contract Ships prebuilt 64-bit efs_Write; pointer-style ioctl returns EINVAL (-22) on MSM8974 kernel, and MEMORY_DEVICE_MODE blocks EFS ops. Source-available 32-bit C pp_regconfig_provision_v6 (PolyForm Noncommercial 1.0.0; commercial license available).
Baseband EFS Scope Writes 1 byte (IMS_enable=01). Live-tested on Passport (1.61/1.62/1.81): still fails with CAUSE_CODE 54 READ_FAILED & NOT_REGISTERED. Decompressed 11.7MB Q6ZIP Hexagon firmware to build Stage 6A: 54 coordinated EFS/DS items (405B qp_ims_reg_config + 789B IPV4V6 profile4 + standalone DCM).
Android Stack & Caller ID Zero Android app code (README mentions of qcril.db and boot scripts are unimplemented in its 4 shell scripts). Clean-room Qcom32VolteIms.apk v2.7 (rild_ims0 protobuf engine, persistent CarrierConfig, 3GPP CLIP→OIR + TOA=145 Caller ID fix).
Root & Rollback Safety Requires Magisk; auto_enable_volte.sh performs no backup, writes even after read failure, and has no rollback tool. Inspection logs contain state and hashes only; fixed rollback does not guarantee original-value restoration.

What is the license?

Source-available (PolyForm Noncommercial 1.0.0; commercial license available). Commercial license.

Magisk?

The tested ROM supports ADB Root for desktop use; root support varies by ROM.

SELinux / EFS

The tested device remained Enforcing; independently back up device EFS before writing.

Are Silver and other editions verified?

No. oslo, wichita, keian, wseries and windermere are not hardware verified; source defaults to read-only with rollback available. Old releases lack the new gate.

How does upgrading from legacy org.passport.volteims work?

Automatically. Deploying or upgrading with v1.2.3-r1 cleans up legacy org.passport.volteims overrides and migrates cleanly to org.octolab.qcom32ims (v2.7).

Does incoming Caller ID work properly?

Yes. Qcom32VolteIms v2.7 translates 3GPP CLIP presentation values into Android’s ImsCallProfile.OIR_* constants, normalizes TOA=145 international numbers, and pushes callSessionUpdated so incoming numbers match Contacts cleanly.

Does rollback restore original bytes?

Not guaranteed. Inspection logs are not full backups; fixed cleanup writes 00 and deletes items. Make an independent backup first.

Can I rely on this for emergency calls (911/112/110)?

No. This is an experimental community hardware-preservation project and has not undergone emergency services certification (E911 / IMS Emergency PDN). Do not rely on modified legacy devices as your sole emergency phone.
